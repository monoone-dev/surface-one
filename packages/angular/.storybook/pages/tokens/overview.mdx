# Design tokens

Every design value Surface One uses — colour, radius, spacing, shadow, blur, motion, type — is a CSS
custom property. Components consume `var(--token)` and nothing else. The design-system **core is
shadcn/ui 1:1**; skins are **theme override layers** (`.claude/rules/angular-zoneless.md` §6c).

| File                                                        | What it holds                                                              |
| ----------------------------------------------------------- | -------------------------------------------------------------------------- |
| `packages/tokens/src/tokens/typography.css`                 | Skin-invariant type steps and note/prose surfaces                          |
| `packages/tokens/src/tokens/layout.css`                     | Spacing (4px base), layout widths, the sidebar rhythm, shell geometry      |
| `packages/tokens/src/tokens/scale.css`                      | Stacking ladder, dialog / sheet widths, invariant component steps          |
| `packages/tokens/src/tokens/accents.css`                    | User-selectable accent palettes (`data-accent`) — beat any skin default    |
| `packages/tokens/src/themes/minimalist.light.theme.scss`    | **The base**: every themed token, shadcn Nova + Neutral + Geist            |
| `packages/tokens/src/themes/minimalist.dark.theme.scss`     | Minimalist dark                                                            |
| `packages/tokens/src/themes/studio.{light,dark}.theme.scss` | Studio — Vega + Nuxt UI "Sky", soft aurora gradient (`data-skin="studio"`) |
| `packages/tokens/src/themes/paper.{light,dark}.theme.scss`  | Paper — Maia, tuned for reading (`data-skin="paper"`)                      |

## Rules (binding — `.claude/rules/angular-zoneless.md` §6 / §6c)

- **Tokens are the only source of design values.** No raw hex / px / rgba in component SCSS. A
  one-off structural size (a `min-width`) is fine; anything the design language names is a token.
- **A missing value means a new token** — its shadcn value goes in
  `minimalist.light.theme.scss`; every other theme file re-declares it only where it differs.
- **Overlays are opaque.** Anything floating over content uses `--surface-overlay` with no
  backdrop blur, `--border-strong` and `--shadow-lg` (T3). `--surface-raised` / `.card` is for
  in-flow panels.
- **No glass.** Surfaces are flat and opaque in every skin — no backdrop blur, saturate, veils,
  lensing rims or glass highlights. Studio's only atmosphere is the `--aurora-*` gradient field
  behind the page.

## Three independent axes

The toolbar above switches the same attributes the app stamps on `<html>`:

| Toolbar | Attribute                                   | Set by          |
| ------- | ------------------------------------------- | --------------- |
| Theme   | `data-theme="dark" \| "light" \| "system"`  | `ThemeService`  |
| Accent  | `data-accent="blue" \| …` (absent = purple) | `ChromeService` |
| Skin    | `data-skin="paper"` (absent = Studio)       | `ChromeService` |

`data-theme` decides how **bright** the app is, `data-skin` what it is **made of**, and
`data-accent` its **tint**. Every catalogue page shows the _declared_ value and the _live_ value
resolved under the current toolbar selection.
